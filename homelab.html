ROOM 1

The Foundation

Everything else in this tour depends on two boxes sitting in a closet: one that runs computers inside computers, and one that never forgets a byte.

🖥

Proxmox VE

the hypervisor

This is the one machine that everything else technically runs "inside of." A single physical server — a 10-core Xeon with 128GB of ECC memory — is carved up into a dozen virtual machines and containers, each one thinking it has the whole computer to itself.

ECC memory matters more here than on a normal desktop: a silent bit-flip in regular RAM can quietly corrupt every VM running on top of it, and ECC catches that in real time. The 20 available threads mean the firewall, storage, Windows Server, and a dozen Docker containers can all run at once without fighting each other for CPU time.

💾

TrueNAS Core

the memory

A second box holds every VM snapshot and backup on a 4+TB ZFS pool. Standard RAID can silently hand back corrupted data with no warning — ZFS checksums every block on every read, so quiet corruption gets caught instead of copied into the next backup.

🎮

Client Nodes

the everyday hardware

A gaming PC and a PS5 live on the network too, but they're kept on their own segment with no path back to the hypervisor or storage — so if one ever got compromised, it would hit a wall before it reached anything that matters. They're also where I test new firewall rules before trusting them anywhere else.

ROOM 2

Follow a Packet Home

Say a laptop on the WiFi tries to reach the file server. It hits the firewall first, gets inspected, then lands on a managed switch that tags every device into one of four segments. From there, the rule is simple: unless a segment is explicitly allowed to talk to another, it can't. A compromised smart bulb on the IoT segment physically cannot reach the NAS — not because of a setting somewhere, but because the packet gets dropped before it ever arrives.

This is the same segmentation model used in enterprise and cloud networks — the homelab version just has fewer users and more consoles.

FOUR SEGMENTS, ONE RULE — DENY BY DEFAULT:

VLAN 10 · Admin — Proxmox, TrueNAS, and firewall management. Reachable only over the WireGuard VPN or in person.

VLAN 20 · Clients — gaming PC, PS5, streaming. Free internet access, no path into anything else.

VLAN 30 · IoT & guests — smart home devices. Outbound HTTPS only, and Pi-hole blocks tracking and known malware domains network-wide.

VLAN 40 · VPN — remote laptop and phone, authenticated by public key rather than password. Even a stolen key can't pivot into the client or IoT segments.

Here's what that deny-by-default rule actually looks like once it's written down:

opnsense_fw_rules.txt 
# default policy on every VLAN interface: DENY ALL
# everything below is an explicit exception

VLAN 10 (Admin)   → Any        : ALLOW
VLAN 20 (Clients) → WAN        : ALLOW
VLAN 20 (Clients) → VLAN 10/30/40 : DENY
VLAN 30 (IoT)     → WAN :443   : ALLOW
VLAN 30 (IoT)     → Any VLAN   : DENY
VLAN 40 (VPN)     → VLAN 10    : ALLOW
VLAN 40 (VPN)     → VLAN 20/30 : DENY

# any DNS bypass attempt gets redirected here
Any VLAN → UDP/TCP 53 → REDIRECT → Pi-hole@10.0.10.5

ROOM 3

The Practice Lab & the Everyday

This room does two jobs. Half of it is a sandbox for practicing enterprise Windows administration with nothing real on the line. The other half quietly runs the actual services I use every day — including the site you're reading right now.

THE PRACTICE LAB — THREE VMS THAT MIRROR A REAL DOMAIN:

Windows Server 2025 runs as a domain controller — Active Directory, Group Policy, DNS and DHCP for the domain. No study guide replaces doing OU design and GPO troubleshooting live.

An Ubuntu Server VM is where scripts and packages get tested before anything touches production — the same dev-to-prod pipeline real infrastructure teams use, just scaled down.

A Windows 10 client stays domain-joined so every GPO and firewall rule gets verified from an actual end user's point of view before I'd trust it anywhere else.

THE EVERYDAY — ONE ALPINE CONTAINER, TEN-PLUS SERVICES:

All of it runs in Docker inside a single lightweight Alpine LXC — using less RAM than one Windows VM while running everything below. Portainer gives a GUI over the containers, config stays versioned in GitHub, and Uptime Kuma and Nagios keep an eye on all of it. The rest covers day-to-day use: a WordPress sandbox, Vikunja for tasks, Navidrome and Audiobookshelf for media, and The Lounge for IRC.

Running Docker inside an LXC stacks two isolation layers — a problem in one container can't touch the host, and it's the same pattern behind how Kubernetes runs pods on container-optimized nodes in the cloud.

GOING PUBLIC — HOW THIS SITE (AND MY LEDGER APP) ACTUALLY REACH THE INTERNET:

Two of these services are actually public: this portfolio, and a full-stack budgeting app I built myself — its own React-style frontend plus a real database, tracking my own finances and budget. Both live on my own domain and get there the same way. A push to GitHub triggers Coolify to build and deploy the container. NGINX handles the reverse proxy, routing each subdomain to the right container instead of exposing raw ports. Cloudflare sits in front of all of it — managing DNS, proxying traffic so my home IP is never exposed directly, and issuing and auto-renewing the SSL certificates that keep everything on HTTPS.

ROOM 4

What Happens When Something Breaks

Every design choice in this homelab assumes something eventually will break — a drive, a bad update, a fat-fingered config change. The question that actually matters is how fast it recovers.

01

Hourly — Proxmox snapshots let any single VM roll back to any hour, without touching anything else.

02

Daily — everything replicates from Proxmox to TrueNAS over ZFS, so a full copy survives even if the hypervisor itself dies.

03

Weekly — Plex metadata gets its own snapshot. Rebuilding that from scratch takes hours; from backup, under five minutes.
